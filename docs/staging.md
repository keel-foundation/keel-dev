# Stage mode

The public demo runs mocked by default. Stage mode connects it to real stage services without putting their URLs or tokens in browser code.

## How it works

The local demo server exposes two same-origin proxy prefixes:

| Demo path | Proxied to |
|---|---|
| `/api/*` | `TUBEKEEL_API_BASE_URL` + `/api/*` |
| `/moderation/*` | `TUBEKEEL_MODERATION_BASE_URL` + `/*` |
| `/config.js` | Generated by the demo server; no token |

The browser only talks to `http://localhost:3000`. The demo server adds the bearer token, so the token never reaches the browser.

## Run against stage

```sh
TUBEKEEL_MODE=remote \
TUBEKEEL_API_BASE_URL=https://stage-api.example.org \
TUBEKEEL_MODERATION_BASE_URL=https://stage-moderation.example.org \
TUBEKEEL_OPENAPI_URL=https://stage-api.example.org/openapi.yaml \
TUBEKEEL_DEMO_TOKEN=replace-with-a-stage-demo-token \
make demo
```

Use the API and moderation origins, not paths ending in `/api` or `/v1`. Replace the example URLs and token with the values provided by a maintainer. Do not commit them.

The demo uses these moderation endpoints:

- `GET /v1/demo/state`
- `POST /v1/demo/reset`
- `POST /v1/actions`
- `POST /v1/actions/{action_id}/appeal`
- `POST /v1/appeals/{appeal_id}/decide`
- `GET /v1/ledger/verify`
- `GET /v1/ledger/export?format=jsonl`

It uses `GET /api/v1/videos/demo` from core for the video metadata.

## OpenAPI

Set `TUBEKEEL_OPENAPI_URL` to the stage OpenAPI document. The demo shows a link in the footer.

Use the OpenAPI document to:

- confirm endpoint paths and response shapes;
- check required fields before changing any service;
- compare stage behavior with `keel-spec/schemas/openapi.yaml`.

If an endpoint is missing from stage, the demo shows the error returned by the proxy. It does not silently switch to mock data.

## Mock mode

```sh
make demo
```

Mock mode requires no backend. The demo simulates the signal, case, action, appeal, independent review, and hash-chained ledger in the browser. Use it for UI and documentation work, screenshots, and flow review.

## Limitations

- Stage may reject the demo token or lack the demo endpoints; the UI shows the error.
- The demo is not a production client. It has no real user login and no production authorization.
- The proxy is for local development only. A production deployment needs a proper reverse proxy and authentication.
- Do not expose the demo server to the public internet.

Full-stack local setup is maintainer-only and lives in the private `keel-infra` repository.
